# BOE dual-model machine-learning force field

This project provides a BOE-based dual-model machine-learning force field for
predicting atomic forces and total energies and running molecular dynamics (MD).
It includes the workflow for extracting training labels from VASP outputs,
generating BOE descriptors, training and evaluating the models, and using them
in MD simulations.

## Getting started

- **Use a trained model:** install the dependencies, prepare a compatible model
  bundle as described in [Using a trained model](#using-a-trained-model), then
  follow [Run molecular dynamics](#4-run-molecular-dynamics).
- **Train your own model or reproduce the workflow:** start with
  [Prepare complete VASP outputs](#1-prepare-complete-vasp-outputs) and follow
  the data preparation, training, and MD steps in order.

**Availability:** this repository currently provides code and reference resources,
but does not include training trajectories or a validated pretrained-model
bundle. To run MD, you need compatible trained weights and their matching
normalization statistics, either supplied separately or generated by training.

## Scope and prerequisites

The current workflow targets the supplied 80-atom phosphorus reference system,
with two BOE modes and 20 BOEs per mode per structure. Force alignment and dataset
grouping assume these counts; arbitrary compositions and cell sizes are not a
supported general training interface.

Use Python 3.11 or newer (the regression tests use Python 3.11 unittest helpers).
Install dependencies:

```powershell
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

`requirements.txt` lists direct dependencies, not a certified version lock.
Choose the PyTorch build appropriate for your CPU/CUDA environment. The extraction
scripts require Bash and awk (Linux, WSL, or Git Bash); Python stages also run on
Windows. VASP must be obtained and run separately under its own license.

## Using a trained model

You can skip VASP data extraction and training if you already have a compatible
model bundle. You need:

- Both subnet weight files: `model1.pth` and `model2.pth`.
- The matching training-set statistics: `ds_train_stat1.csv` and
  `ds_train_stat2.csv`.
- The reference structure used to define BOE atom ordering, plus an initial
  structure with compatible atom ordering.
- The model input dimension, hidden width, and training energy offset.

Keep these resources together. Statistics from another training run or a
different reference-index convention are not interchangeable with the weights.
The [MD example](#4-run-molecular-dynamics) uses paths produced by the training
workflow below; replace them with your bundle paths and configuration when
using separately supplied weights.

## 1. Prepare complete VASP outputs

For each temperature, use this layout:

```text
100/
    OUTCAR
    XDATCAR
    all_energy.txt
    forces_only.dat
200/
...
600/
```

From inside each temperature directory, extract all ionic-step data:

```bash
bash ../ext_force.sh
bash ../ext_energy.sh
```

Keep the complete matching XDATCAR, force series, and energy series. Apply frame
selection only during the sampling step below, rather than trimming individual
inputs independently. The extraction scripts write through a temporary file so
malformed or missing input does not replace an existing output with partial
results.

Forces are columns 4-6 of each OUTCAR `POSITION ... TOTAL-FORCE` block, in eV/A.
Energy is field 4 of `energy  without entropy` lines, in eV, matching the supplied
energy extraction convention. Check that your OUTCAR format and chosen energy
definition match before using other VASP configurations.

This repository starts from completed VASP outputs. It does not include a
validated INCAR/KPOINTS template or a VASP job submission workflow. Reproducing
the underlying first-principles calculations additionally requires the original
VASP settings and pseudopotential choices. VASP binaries and licensed POTCAR
files are not distributed here.

## 2. Select frames and build datasets

Run these commands from the repository root:

```powershell
python plot_hist_v2.py
python gen_center_all_data.py
python gen_force_all_data.py
```

Generated files go to `low_temp_v2`. The dataset split is structure-level
70%/15%/15% train/validation/test with seed 42, using the same split for both modes.
A random split of a trajectory does not establish independence between nearby
frames; use additional independent trajectories to assess generalization.

### Sampling and frame alignment

The default sampling configuration is:

| Parameter | Value |
| --- | --- |
| Temperatures | 100, 200, 300, 400, 500, 600 K |
| Raw trajectory window | `[500, 4000)` |
| Candidate stride | 2 |
| Energy bins | 10 |
| Samples per temperature | 800 (4800 total) |
| Sampling seed | 42 |

`frame_index` is a **zero-based index into the complete raw trajectory**, not
an index relative to the sampling window. Each saved energy must match
`all_energy.txt[frame_index]`. The data preparation scripts check frame counts,
energy correspondence, and incomplete force blocks; a missing selection file
raises an error rather than silently selecting all frames.

Use structures, forces, and energies from the same VASP run in identical frame
order. Equal frame counts alone do not prove physical correspondence. Check
duplicate or missing boundary steps before combining restart outputs.

## 3. Train and evaluate

```powershell
python train_drift_weight_sweep.py --drift-weights 0.05 --dry-run
python train_drift_weight_sweep.py --drift-weights 0.05
```

The documented defaults use 42 input features, width 128, energy offset +429.825
eV, and training seed 30. Each run writes weights, history, validation/test
summaries and diagnostic plots under `resultsweep_low_temp_v2`.

Export statistics from the **same training datasets** used for these weights:

```powershell
python stat_save.py --all_temp_root low_temp_v2 --n_col 42
```

Do not replace the training CSVs after training and then export statistics for
older weights. Keep each pair of weights, both statistics files, reference
structure, training summary, and dataset/split provenance together.

## 4. Run molecular dynamics

After training, or after obtaining a compatible model bundle, start with a short
smoke run before attempting a production trajectory. This example uses the
configuration and output paths from the training command above:

```powershell
python md_cpu_dual.py --model1 resultsweep_low_temp_v2\dw_0p050\model1.pth --model2 resultsweep_low_temp_v2\dw_0p050\model2.pth --stat1 low_temp_v2\ds_train_stat1.csv --stat2 low_temp_v2\ds_train_stat2.csv --poscar POSCAR_REV.vasp --ref-poscar POSCAR_REV.vasp --width 128 --input-dim 42 --stat-n-col 42 --energy-offset -429.825 --temperature 300 --dt 0.0001 --steps 10 --checkpoint 10 --traj 1 --seed 12345 --remove-com-velocity --output md\smoke
```

The timestep argument is in ps (`0.0001 ps = 0.1 fs`). The negative energy offset
reconstructs physical energy from the positively shifted training labels.
Use `python md_cpu_dual.py --help` for ensemble and restart settings.

The network directly predicts forces; this code does not by itself establish
that they are gradients of the predicted energy. Check independent force errors,
temperature behavior, net-force drift, structural stability, and NVE energy drift
before treating a trained model as suitable for production MD.

## Testing and reproducibility status

Run the regression tests with:

```powershell
python -m unittest discover -s tests -v
```

The 10 tests cover frame-index and energy alignment, malformed or incomplete
inputs, Bash extraction, and consistency between training and MD normalization.
Bash extraction tests require Bash/awk and are skipped when the required shell
is unavailable.

Checks have passed in a Python 3.11.5 environment, including sampling 4800 frames
from real energy inputs and building both-mode datasets from a 12-frame real
subset. These checks validate data handling, not model accuracy or MD stability.
A full retraining and trained-model MD validation have not yet been completed
for this code version, and dependency versions are not yet locked.

When reproducing a result, record the input data and VASP settings, frame
selection and split metadata, dependency versions, training arguments, both
weight files, and their matching normalization statistics. Evaluate the resulting
model on independent data before reporting accuracy or using it for production
simulations.
